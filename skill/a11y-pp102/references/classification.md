# Классификация замечаний

## Тип: кто исправляет

**Вёрстка** — решение одно и подходит для всех текущих и будущих случаев: семантика тегов, ARIA, CSS (контраст, фокус, переполнение), JS-поведение компонента, текст, который можно вписать в шаблон один раз (название кнопки «Закрыть окно», подпись поля).

**Контент** — нужно отдельное решение человека для каждого случая: `alt` конкретной фотографии, описание конкретного видео, расшифровка, реальные названия категорий вместо заглушек, доступный PDF вместо скана, недостающие данные (e-mail, телефон). Признак — рекомендация звучит как «например, …»: это образец формулировки, а не готовое значение.

Фронтенд делает для контента инфраструктуру и помечает остаток:
- убрать мусорные значения по умолчанию (`alt="Image"`, `lorem ipsum`, «Один», «Два»);
- сделать поле обязательным в компоненте или в CMS;
- подготовить место под описание видео, альтернативную версию документа;
- описать в журнале, что и кому нужно заполнить.

**Бэкенд** — нужны данные или логика сервера, которых нет во фронтенде: количество результатов поиска, параметры выдачи, серверная валидация и тексты ошибок, генерация `<title>`, редиректы, отдача документов.

Быстрый тест:
- можно один раз вписать значение в шаблон, и оно будет верным всегда → вёрстка;
- для каждого нового элемента нужно, чтобы человек решил, что написать → контент;
- нужны данные или поведение, которых физически нет на фронтенде → бэкенд.

Не имитируй контент и бэкенд во фронтенде (выдуманные `alt`, захардкоженные счётчики) — это скрывает проблему от владельца.

## Критичность

| Уровень | Когда | Что делать |
|---|---|---|
| **Блокер** | Прямое нарушение подпункта п. 2 ПП № 102, из-за которого пользователь с нарушением зрения не может получить информацию или выполнить задачу: элемент недоступен с клавиатуры, форма не проходится, контент не читается скринридером, текст не масштабируется | Исправлять в первую очередь |
| **Существенно** | Нарушение не блокирует задачу полностью, но заметно мешает: нужно больше времени, обходные пути, пользователь дезориентирован; спорные и пограничные случаи по подпунктам | Исправлять обязательно, после блокеров |
| **Улучшение** | Прямого нарушения подпункта нет, но снижается удобство и доверие: лишний шум скринридера, неточные формулировки, рекомендации WCAG сверх требований | Исправлять по возможности |

## Статусы в журнале

| Статус | Значение |
|---|---|
| ✅ Сделано | Исправлено и проверено |
| ⚠️ Частично | Исправлено иначе, чем в рекомендации, или исправлена только инфраструктура (остаток — контент или бэкенд) |
| ⏳ В очереди | Вёрстка, ещё не сделано |
| 📝 Контент | Нужно заполнение владельцем контента |
| 🔧 Бэкенд | Нужна правка на сервере |
| ➖ Не подтвердилось | Проблема не воспроизводится или уже исправлена ранее (указать, где) |
