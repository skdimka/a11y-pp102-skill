# Методика проверки

Автоматика находит примерно треть проблем. Остальное — только руками: клавиатура, скринридер, смысл текстов. Делай оба этапа.

## 1. Подготовка

- Список страниц: по одной странице каждого шаблона (главная, раздел, список, карточка, новость, поиск, форма, документы, контакты, 404) плюс страницы с уникальными блоками. Карта сайта (`sitemap.xml`) — хороший источник.
- Список компонентов: шапка, меню, футер, слайдеры, вкладки, фильтры, пагинация, формы, модальные окна, видео, аккордеоны, таблицы, карты.
- Браузеры: Chrome или Edge + NVDA (Windows), Safari + VoiceOver (macOS, iOS), по возможности TalkBack (Android).

## 2. Автоматические проверки

Скрипты в `scripts/` репозитория скилла (Node 18+, Playwright):

```bash
cd scripts
npm install
npx playwright install chromium
node axe-scan.mjs --urls urls.txt --out reports/axe.md
node reflow-200.mjs --urls urls.txt --out reports/reflow.md
node keyboard-walk.mjs --url https://example.ru/ --out reports/keyboard.md
```

- `axe-scan.mjs` — axe-core по WCAG 2.x A/AA, результаты сгруппированы по подпунктам ПП № 102.
- `reflow-200.mjs` — эквивалент браузерного зума 200% (окно 1280×800 → 640×400 CSS px): горизонтальная прокрутка страницы, элементы за правым краем, обрезанный текст.
- `keyboard-walk.mjs` — проходит страницу Tab: порядок фокуса, элементы без видимого фокуса, фокус на невидимых элементах, элементы без доступного имени, ловушки фокуса; плюс кликабельные элементы вне порядка Tab, ссылки без контекста, заглушки `#`, одинаковый текст с разными адресами, поля с подписью только в placeholder.

Результаты скриптов — кандидаты в замечания, а не готовые замечания. Каждое проверь глазами: эвристики дают ложные срабатывания. Частые:

- за край контейнера выходит декоративная картинка, а не текст;
- слайдер со свободной прокруткой выглядит как обрезанный ряд;
- намеренное усечение текста (line-clamp, многоточие) — допустимо, если полный текст доступен на детальной странице или по кнопке;
- фокус уходит внутрь iframe (PDF, карта, видео) — дальше обход руками.

Прототип или статическая сборка: собери проект и раздай папку сборки локальным сервером (`python3 -m http.server`), а не через `file://` — иначе абсолютные пути к скриптам и стилям не загрузятся. Страницы-фрагменты для AJAX (`*-response.html` и подобные) в список не включай.

Когда axe и обход Tab показывают сотни одинаковых нарушений, ищи общий компонент: почти всегда это один миксин (кнопка, поле, картинка, слайдер), и одна правка закрывает их все.

## 3. Ручная проверка по подпунктам

**«а» Клавиатура.** Отключи мышь. Tab по всей странице: каждый интерактивный элемент достижим, фокус виден на любом фоне, порядок логичен, ни во что не проваливаешься. Открой и закрой каждое меню, окно, аккордеон, вкладку, слайдер, видео. Esc закрывает всплывающее, фокус возвращается.

**«а» Скринридер.** Навигация по заголовкам (иерархия без пропусков, один `h1`), по ориентирам (`header`, `nav` с именами, `main`, `footer`), по ссылкам и полям форм. Состояния озвучиваются: «развёрнуто», «выбрано», «текущая страница», «обязательное», «недопустимое значение».

**«б» Масштаб.** Окно 1280×800, зум 200%, затем 400% для контроля (WCAG 1.4.10 — ширина 320 px). Нет горизонтальной прокрутки страницы; ничего не перекрывается и не обрезается; меню и окна прокручиваются внутри себя; всё достижимо.

**«в» Документы.** Для каждого типа документов — открыть пару файлов: есть текстовый слой, теги, язык; ссылка на файл содержит название, формат и размер.

**«г» Нетекстовое.** Пройти все изображения: содержательные описаны, декоративные скрыты, иконочные кнопки названы. У видео — описание, субтитры или расшифровка.

**«д» Капча.** Пройти формы с капчей скринридером.

**«е» Заголовки.** `<title>` уникален на каждом шаблоне; `h1` отражает тему.

**«ж» Ссылки.** Список ссылок скринридера: нет «Подробнее» без контекста, нет дублей с разными адресами, внешние и файлы помечены. Выборочно перейти по ссылкам: текст совпадает с целевой страницей.

**«з» Контраст.** Пипеткой — все цвета текста во всех состояниях и темах; текст на фото — в самых светлых и тёмных точках.

**«и» Не только цвет.** Ошибки форм, активные вкладки, фильтры, пагинация, статусы — есть текст или программное состояние.

**«к» Движение.** Всё, что движется дольше 5 секунд, можно остановить; видео не стартует само; при `prefers-reduced-motion` анимации выключаются (эмуляция в DevTools → Rendering).

**«л» Наведение.** Провести мышью по меню и карточкам: ничего не открывается неожиданно, всплывающее можно закрыть Esc и навести на него указатель.

**«м» Формы.** Отправить пустую форму, форму с ошибками, правильную — со скринридером. Подписи, форматы, ошибки и результат отправки озвучиваются.

**«н» Шрифт.** Основной текст набран читаемой гарнитурой; символы различимы; увеличенные межстрочные и межбуквенные интервалы (букмарклет text spacing) не ломают блоки.

## 4. Оформление замечаний

Каждое найденное — строкой в таблицу по `templates/audit-table.md`: код, страница, компонент, подпункт, WCAG, критичность, что не так, как воспроизвести, что ожидается, рекомендация, тип. Одна строка — одна проблема одного компонента; если проблема повторяется на многих страницах — одна строка с перечнем страниц.
